# tools/gen — синтетические данные T1 и golden-файлы

Go-модуль `marktrace/gen` (только stdlib). Генерирует детерминированный набор данных
кейса 16 по SPEC §9 и эталонные (golden) результаты его импорта.

```sh
cd tools/gen
go run . -seed 16 -out ../../        # сгенерировать и сразу самопроверить
go run . -check-only -out ../../     # только самопроверка уже лежащих файлов
go test ./...                        # тесты генератора и независимого чекера
```

Что пишется (пути относительно `-out`):

| Файл | Содержимое |
|---|---|
| `data/C16/T1/items.csv` | 96 корректных товаров + 3 битых (в конце) |
| `data/C16/T1/codes.csv` | 512 корректных кодов (в порядке выпуска) + 6 битых строк (в конце) |
| `data/C16/T1/operations.csv` | 862 корректные операции (по возрастанию ts, `OP-000001…`) + 8 внедрённых строк |
| `data/C16/mock_registry.csv` | `code`: 512 корректных кодов T1 + 30 демо-кодов |
| `data/C16/demo_codes.csv` | `code,item_code`: 30 кодов, которых нет в T1, для живой демонстрации через форму |
| `golden/status_summary.csv` | `status,count`: issued 300, introduced 110, sold 78, returned 12, disposed 12 |
| `golden/violations.csv` | 18 нарушений, формат и сортировка по SPEC §7 |

## Как устроены данные

- Товары: группы, подлежащие маркировке в РФ (молочная продукция, обувь, парфюмерия,
  шины, упакованная вода, одежда, БАДы, велосипеды, пиво); бренды вымышленные. Префиксы
  GTIN — российские `460–469`, у одного бренда один префикс компании. 19 из 96 товаров
  (~20%) с GTIN-13, остальные GTIN-14 с ведущим нулём. Названия содержат запятые и
  кавычки — проверка RFC 4180.
- Акторы: `op-prod-01…05` (выпуск и ввод, по товарной группе), `op-shop-01…08`
  (продажа, возврат, списание).
- Время: 1 сентября – 31 октября 2026, рабочие часы 08:00–20:59, смещение `+03:00`.
  У каждого кода время операций строго возрастает; все моменты в файле уникальны.
- Истории корректных кодов: только выпуск (300), ввод (110), продажа (70), продажа →
  возврат (12), списание после ввода/продажи/возврата (6/4/2), цепочка
  продажа → возврат → продажа (8).
- K1 = 862 / (862 + 7) = **99,19%**.

## Внедрённые ошибки (seed 16)

Номер строки — строка файла, заголовок = строка 1. Битые строки всегда дописываются
в конец в фиксированном порядке; ключи зависят от seed — актуальную таблицу печатает
`go run .`.

| Файл | Строка | Ключ | Результат | Что сделано |
|---|---|---|---|---|
| items.csv | 98 | `ITM-0097` | GTIN_CHECKSUM | GTIN-13 с неверной контрольной цифрой |
| items.csv | 99 | `ITM-0098` | GTIN_CHECKSUM | GTIN-14 с неверной контрольной цифрой |
| items.csv | 100 | `ITM-0099` | GTIN_FORMAT | латинская буква O вместо цифры в GTIN |
| codes.csv | 248 | `0104606409275467213wNpCd` | SNAPSHOT_MISMATCH | ожидается returned, фактически sold |
| codes.csv | 307 | `010469355113939621m5ygCa` | SNAPSHOT_MISMATCH | ожидается sold, фактически introduced |
| codes.csv | 514 | `(01)04660761090717(21)LKNJq7` | CODE_FORMAT | код в человекочитаемом виде GS1 со скобками |
| codes.csv | 515 | `010464161971781921D7NLC` | CODE_FORMAT | серийный номер из 5 символов вместо 6 |
| codes.csv | 516 | `010466346857789521HRP2zo` | DUPLICATE_CODE | повтор принятого кода с другим товаром ITM-0095 (исходно ITM-0011) |
| codes.csv | 517 | `010462426230535021pOQkhz` | DUPLICATE_CODE | повтор принятого кода с другим товаром ITM-0076 (исходно ITM-0089) |
| codes.csv | 518 | `010460788795369421UKt8nZ` | GTIN_MISMATCH | код содержит GTIN товара ITM-0070, а привязан к ITM-0027 |
| codes.csv | 519 | `010465361792594321Zp2jWA` | ITEM_NOT_FOUND | товара ITM-0200 нет в справочнике |
| operations.csv | 864 | `OP-000863` | TRANSITION_NOT_ALLOWED | продажа кода, который только выпущен (issued) |
| operations.csv | 865 | `OP-000864` | TRANSITION_NOT_ALLOWED | повторное списание (disposed — финальный статус) |
| operations.csv | 866 | `OP-000865` | TRANSITION_NOT_ALLOWED | повторная продажа уже проданного кода |
| operations.csv | 867 | `OP-000866` | TIME_REVERSED | продажа введённого кода с временем раньше ввода |
| operations.csv | 868 | `OP-000867` | CODE_NOT_FOUND | корректный по маске код, отсутствующий в реестре и в моке |
| operations.csv | 869 | `OP-000868` | VALUE_FORMAT | неизвестный тип операции `transfer` (новый op_id) |
| operations.csv | 870 | `OP-000800` | IDEMPOTENCY_CONFLICT | op_id уже принят; те же code/op_type/ts, другой actor |
| operations.csv | 871 | `OP-000664` | duplicate (не нарушение) | точный повтор принятой строки |

Почему каждая строка падает именно с этой причиной при порядке проверок §2.3:

- Отклонённые строки `codes.csv` не попадают в реестр, и операций по ним нет.
  DUPLICATE_CODE ловится на шаге 2 (до формата), остальные — на своём шаге.
- SNAPSHOT_MISMATCH — обычные корректные строки, у которых намеренно неверен только
  ожидаемый статус (ts совпадает с фактическим).
- `TIME_REVERSED`: переход introduced → sell разрешён (шаг 9), а ts на 20–60 минут раньше
  ввода и строго позже выпуска, так что пары (code, ts) не совпадают (шаг 6).
- `CODE_NOT_FOUND`: код корректен по маске, в `code_registry` нет, op_type `sell` — шаг 7.
- `VALUE_FORMAT` и три `TRANSITION_NOT_ALLOWED` идут с новыми op_id, поэтому шаг 2 пройден.
- Отклонённые операции не меняют состояние, поэтому ожидаемые статусы в `codes.csv`
  равны реальным итоговым (кроме двух SNAPSHOT_MISMATCH).

## Самопроверка

Golden получается из того, что генератор сам внедрил (по построению). Независимо от
этого пакет `check/` заново реализует правила §2.3 (собственные помощники GTIN/маски,
без кода backend), проигрывает файлы T1 в файловом порядке и требует:
точное совпадение с `golden/*.csv`; размеры в диапазонах §9; ровно 7 отклонённых и
1 дубль операций; 3 отклонённых товара и 6 строк кодов; K1 ≥ 99%; доля GTIN-13 ≈ 20%;
каждый из 5 статусов встречается. Это выполняется после каждого `go run .` и в тестах
(seed 16, 1, 2, 42, 2026). `TestCommittedFilesUpToDate` следит, чтобы файлы в репозитории
совпадали со свежей генерацией с seed 16.
