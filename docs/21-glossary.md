# 21. Глоссарий и перечень сущностей

**MarkTrace · версия 1.0 · 16.11.2026**

## 1. Назначение

Итоговый глоссарий (ПР-13) — единый язык проекта: им пользуются аналитик, разработчики, интерфейс и документы. Определения согласованы с `SPEC.md` (rules_version `2026.11-1`), кодом `backend/internal/*` и схемой `backend/internal/store/migrations/001_init.sql`. Перечень сущностей в разделе 9 повторяет реальную схему БД. Контексты и события — в [Event Storming](20-event-storming.md).

Правило: в коде, API и CSV используется английский идентификатор из колонки «Идентификатор», в интерфейсе и документах — русский термин. Синонимы из колонки «Не путать» не используются.

## 2. Предметная область маркировки

| Термин | Определение | Идентификатор / где в системе | Не путать |
|---|---|---|---|
| Маркировка | Нанесение на каждую единицу товара уникального кода и учёт его движения в государственной системе | — | — |
| ГИС МТ «Честный знак» | Государственная информационная система мониторинга товаров с обязательной маркировкой | E3; не подключается | — |
| ЦРПТ | Центр развития перспективных технологий — оператор ГИС МТ | В MVP — только мок `POST /cz/verify` | — |
| Мок-сервис ЦРПТ | Учебная замена проверки кода у оператора: отвечает, известен ли код и совпадает ли GTIN | E2; сервис `mock`, реестр `data/C16/mock_registry.csv` | Не является ЦРПТ, не хранит состояние |
| Код маркировки (КМ) | Уникальный идентификатор единицы товара. В MVP — учебная строка из 24 символов: `01` + GTIN-14 + `21` + серийный номер из 6 символов | `code` | Не путать с `item_code` (код товара) |
| КИЗ-аналог | Учебный код маркировки как аналог контрольного идентификационного знака: однозначно определяет единицу товара, но не содержит криптографической части; на экранах «Код» и «Выпуск кодов» показывается как Data Matrix ECC 200 с той же 24-символьной строкой (без GS1 FNC1 и криптохвоста), этикетки не печатаются | `code` | Не является боевым кодом ЦРПТ (допущение A1 [карточки](01-project-card.md)) |
| Маска кода | Регулярное выражение формата кода: `^01(\d{14})21([A-Za-z0-9]{6})$`. Группа 1 — GTIN внутри кода, группа 2 — серийный номер | `rules.ParseCode`, `GET /api/rules` → `code_mask` | Боевой код длиннее и содержит криптохвост (идентификаторы применения 91/92) |
| Серийный номер | Шесть латинских букв или цифр после `21`; регистр значим | Часть `code` | — |
| GTIN | Глобальный номер товара GS1: 13 или 14 цифр, последняя — контрольная | `items.gtin` | Хранится как строка, ведущие нули сохраняются |
| GTIN-13 / GTIN-14 | Две допустимые длины. GTIN-13 разрешён с оговоркой кейса | `rules.ValidGTIN` | — |
| Нормализация GTIN | Приведение к 14 цифрам для сравнения: GTIN-13 → `"0" + GTIN-13`, GTIN-14 без изменений. Только для сравнения, обратно не записывается | `rules.NormalizeGTIN` | Не меняет хранимое значение |
| Контрольная цифра | Последняя цифра GTIN по алгоритму GS1 mod-10: веса 3, 1, 3, … справа налево без контрольной цифры | Ошибка → `GTIN_CHECKSUM` | В MVP контрольная цифра GTIN внутри кода отдельно не проверяется: он сравнивается с GTIN товара |
| Товар (номенклатура) | Позиция справочника, к которой привязываются коды | `items`, `item_code` | «Код товара» = `item_code`, а не код маркировки |
| Привязка кода | Однозначное соответствие кода маркировки товару; создаётся строкой `codes.csv` или формой при `issue` | `code_registry` | Не является статусом кода |

## 3. Жизненный цикл кода

| Термин | Операция `op_type` | Допустима из статуса | Новый статус `status` | Статус в интерфейсе |
|---|---|---|---|---|
| Эмиссия, выпуск | `issue` | У кода нет принятой истории; код привязан к товару | `issued` | выпущен |
| Ввод в оборот | `introduce` | `issued` | `introduced` | введён в оборот |
| Продажа (реализация) | `sell` | `introduced`, `returned` | `sold` | продан |
| Возврат | `return` | `sold` | `returned` | возвращён |
| Выбытие, вывод из оборота | `dispose` | `introduced`, `sold`, `returned` | `disposed` | выбыл |

| Термин | Определение | Идентификатор |
|---|---|---|
| Жизненный цикл | Последовательность статусов кода по таблице выше; пропуск стадий запрещён | `rules.NextStatus` |
| Статус кода | Текущее состояние кода, результат последней принятой операции | `codes.status`, `CodeStatus` |
| Финальный статус | `disposed`: после него любая операция отклоняется `TRANSITION_NOT_ALLOWED` | — |
| Повторная продажа | `sell` после `return`; два `sell` подряд запрещены | — |
| Временная целостность | Время каждой следующей принятой операции кода строго больше времени предыдущей | Ошибка → `TIME_REVERSED` |
| Статусная целостность | `codes.status` равен статусу по последней принятой операции; измеряется K2 | `GET /api/kpi` → `k2` |

В реальной системе розничная продажа тоже выводит код из оборота. В учебной модели кейса продажа (`sell`) и выбытие (`dispose`) — разные операции, а после `sell` возможен `return`.

## 4. Операции, проверки и нарушения

| Термин | Определение | Идентификатор | Не путать |
|---|---|---|---|
| Операция | Принятое событие жизненного цикла кода; запись журнала не меняется и не удаляется | `operations`, `op_id` | С попыткой операции |
| Журнал операций (протокол) | Все принятые операции; источник истины для статуса | `operations` | С журналом попыток |
| Попытка операции | Любая поданная операция из формы или строка `operations.csv` с итоговым решением, включая отказы и повторы | `operation_attempts`, `attempt_id` | Попытка, отклонённая по правам (`AUTH_DENIED`), не записывается |
| Решение | Итог попытки: `accepted` — принята, `duplicate` — повтор без изменений, `rejected` — отклонена | `operation_attempts.decision` | С итогом строки импорта (те же значения, другая сущность) |
| Текущее состояние кода (проекция) | Последний статус, время и актор кода; обновляется в той же транзакции, что и операция | `codes` | Со снимком `codes.csv` |
| Предварительные проверки | Проверки 1–10 SPEC §2.3 без блокировки до вызова мока; повторяются под `SELECT … FOR UPDATE` перед записью | `ops.Evaluate` | — |
| Идемпотентность | Повтор той же операции или строки не меняет данных и не создаёт новых строк (K3) | — | — |
| Повтор | Ключ уже встречался с идентичным содержимым: тот же `op_id` (`code`, `op_type`, время как момент UTC, `actor`) или та же пара (`code`, `ts`) с тем же `op_type` и `actor`; либо идентичная строка ранее была отклонена | `duplicate` | Отклонённая из-за `MOCK_UNAVAILABLE` попытка повтором не считается и проверяется заново |
| Конфликт идемпотентности | Ключ уже встречался с другим содержимым | `IDEMPOTENCY_CONFLICT` | Для `codes.csv` такой случай — `DUPLICATE_CODE` |
| Нарушение | Зафиксированный отказ строки или попытки либо расхождение снимка: одна причина, сообщение на русском, версия правил | `violations` | — |
| Расхождение | В интерфейсе — любое нарушение (страница «Расхождения»); в узком смысле — `SNAPSHOT_MISMATCH` | `GET /api/violations` | — |
| Причина (reason code) | Стабильный машинный код причины отказа; ровно одна на отказ — первая не пройденная проверка | `reason` | С `reason` мока (`INVALID_FORMAT`, `UNKNOWN_CODE`, `GTIN_MISMATCH`) — он попадает в сообщение |
| Сообщение | Русский текст причины с деталями | `message` | — |
| Разбор нарушения | Комментарий или закрытие нарушения контролёром; нарушение при этом не меняется | `violation_resolutions`, `action ∈ {comment, close}` | — |
| Состояние нарушения | `open` — закрытия нет, `closed` — есть запись `close`. Вычисляется, отдельного поля нет | Фильтр `state` в `GET /api/violations` | — |
| Источник нарушения | Файл или поток, где найдено нарушение: `items`, `codes`, `operations` (форма тоже даёт `operations`) | `violations.source` | С источником попытки `form` / `import` |
| Ссылка нарушения | Ключ строки: `item_code` для `items`, `code` для `codes`, `op_id` для `operations` | `violations.ref` | — |
| Версия правил | Идентификатор набора правил, по которому принято решение; сохраняется в каждой попытке и каждом нарушении | `rules_version = 2026.11-1` | — |

## 8. Интеграция и термины моделирования

| Термин | Определение |
|---|---|
| `POST /cz/verify` | Запрос к моку `{code, gtin?}` → `{is_valid, reason?}`. Порядок ответа мока: маска → `INVALID_FORMAT`, код не в реестре → `UNKNOWN_CODE`, GTIN не совпал → `GTIN_MISMATCH`, иначе `is_valid=true` |
| Режим мока | `normal`; `slow` — ответ через 5 с, backend отваливается по тайм-ауту 2 с; `error` — HTTP 500; `garbage` — `200 {}`. Переключение `POST /admin/mode` |
| Ручная проверка кода | `POST /api/verify`: ответ мока показывается пользователю и не сохраняется |
| Доменное событие, команда, политика, модель чтения | Элементы Event Storming, см. [20-event-storming.md](20-event-storming.md) §1.1 |
| Агрегат | Граница согласованности: Код маркировки, Товар, Сессия импорта, Нарушение |
| Ограниченный контекст | Учёт операций, Импорт, Проверка / правила, Отчётность, Доступ |
| Shared Kernel | Пакет `backend/internal/rules`, общий для форм и импорта |

Термины вне границ MVP (упоминаются в [карточке](01-project-card.md), в системе отсутствуют): агрегация (короба, паллеты), УКЭП и подписание, ЭДО, печать этикеток DataMatrix и криптохвост, СУЗ и заказ кодов у оператора.

## 9. Коды причин

| Причина | Когда | Где возникает | Сообщение (без деталей) |
|---|---|---|---|
| `AUTH_DENIED` | Роль не допускает действие | Любая команда записи; HTTP 403, нарушение не создаётся | Недостаточно прав для этого действия |
| `REQUIRED_FIELD` | Пустое обязательное поле; для `issue` из формы — `item_code` | items, codes, operations, форма | Не заполнено обязательное поле |
| `VALUE_FORMAT` | Неверное число полей в строке; статус не из `CodeStatus`; тип операции не из `OperationType` | items, codes, operations, форма | Недопустимое значение |
| `CODE_FORMAT` | Код не соответствует маске | codes, operations, форма | Код маркировки не соответствует маске 01 + GTIN-14 + 21 + 6 символов |
| `GTIN_FORMAT` | Не цифры или длина не 13/14 | items | GTIN должен состоять из 13 или 14 цифр |
| `GTIN_CHECKSUM` | Неверная контрольная цифра | items | Неверная контрольная цифра GTIN |
| `GTIN_MISMATCH` | Нормализованный GTIN товара ≠ GTIN в коде | codes, форма (`issue`) | GTIN товара не совпадает с GTIN в коде маркировки |
| `ITEM_NOT_FOUND` | Товара нет в справочнике | codes, форма (`issue`) | Товар не найден в справочнике |
| `CODE_NOT_FOUND` | `issue` по коду без привязки; другая операция по коду без принятой истории | operations, форма | Код маркировки не найден |
| `DUPLICATE_CODE` | Код уже привязан к другому товару; повторный `issue` | codes, operations, форма | Код маркировки уже зарегистрирован |
| `TRANSITION_NOT_ALLOWED` | Переход не допускается из текущего статуса | operations, форма | Недопустимый переход статуса |
| `TIME_FORMAT` | Время не RFC 3339, без смещения или с долями секунды | codes, operations, форма | Время должно быть в формате RFC 3339 с часовым поясом, без долей секунды |
| `TIME_REVERSED` | Время не позже последней принятой операции кода | operations, форма | Время операции не позже последней принятой операции по коду |
| `IDEMPOTENCY_CONFLICT` | Тот же ключ (`item_code`, `op_id` или пара `code` + `ts`) с другим содержимым | items, operations, форма | Повтор ключа с другим содержимым |
| `SNAPSHOT_MISMATCH` | Ожидаемый снимок ≠ текущее состояние кода | codes (сверка снимка) | Итоговое состояние кода не совпадает с ожидаемым |
| `MOCK_INVALID` | Мок ответил `is_valid=false` | Только форма | Мок-сервис ЦРПТ отклонил код |
| `MOCK_UNAVAILABLE` | Тайм-аут 2 с, ошибка сети, не 200, нет `is_valid` | Только форма; ответ `POST /api/verify` | Мок-сервис ЦРПТ недоступен |

Каталог сообщений — `backend/internal/rules/reasons.go`. В [словаре данных](13-data-dictionary.md) §8 перечислены ещё `ITEM_MISMATCH`, `DEPENDENCY_REJECTED`, `TECHNICAL_FAILURE`; в MVP их нет.

## 10. Перечень сущностей

### 10.12. Соответствие ранним моделям

| В [ERD](12-erd.md) и [словаре](13-data-dictionary.md) | В MVP | Комментарий |
|---|---|---|
| `operation_requests` | `operation_attempts` | Попытки формы и импорта; статуса `pending` нет |
| `verification_checks` | `operation_attempts.mock_result` | Отдельной таблицы вызовов мока нет; ручная проверка не сохраняется |
| Привязка кода внутри `codes` | `code_registry` + `codes` | Привязка и ожидаемый снимок отделены от текущего состояния |
| `codes(code, item_code, status, ts)` из карточки | `codes` + `last_actor` | Добавлен последний актор для фильтра отчёта |
| — | `users`, `sessions` | Доступ по ролям (SPEC §4) |
| Строки импорта со статусом `staged` | Только `accepted`, `duplicate`, `rejected` | Каждая строка обрабатывается и фиксируется сразу |
