# 33. Сценарий демонстрации на итоговой защите

**MarkTrace · версия 1.0 · 16.11.2026**

Пошаговый показ MVP на защите 4, не дольше 7 минут. Сценарий проходит пример D16 из кейса (импорт T1, цепочка issue → introduce → sell для двух кодов, return для одного, свод статусов и нарушений, сверка с эталоном) и добавляет к нему управляемый сбой ЦРПТ и разграничение прав. Слайд 25 колоды `export/MarkTrace_checkpoint4.pptx` — краткая версия этого сценария. Что требуется на защите — в [31-checkpoints.md](31-checkpoints.md).

## 4. Если что-то сломалось

| Ситуация | Что делать | Кто |
|---|---|---|
| issue демо-кода → `DUPLICATE_CODE` (код уже занят) | Взять запасные К3 и К4 из шпаргалки. Числа в итоговых счётчиках не меняются | Жраков Артём |
| `IDEMPOTENCY_CONFLICT` на операции | Две операции по одному коду попали в одну секунду (время по умолчанию — время сервера). Подождать секунду и отправить снова | Жраков Артём |
| Сводка KPI красная ещё до шага 3:00 (K1 < 99% или K5 < 100%) | Стенд не чистый: кто-то выполнил операции после `make verify`. Не чинить на защите: показать слайды 3 и 12 и объяснить по README «Эталон рассчитан на чистую БД» | Шиншин Алексей |
| Мок завис в режиме `error` или `slow` | Выполнить «мок: normal», проверить `curl --noproxy '*' localhost:8082/healthz` | Брусникин Максим |
| Импорт идёт дольше 5 с | Это нормально, импорт синхронный. Не нажимать кнопку повторно | Брусникин Максим |
| Интерфейс не открывается или выдаёт 502 | `make ps`; при необходимости `docker compose restart web backend`. Если за 30 с не поднялось — запасной показ: слайды 5–13 со снимками и `make demo` в терминале. `make demo` проходит шаги 3:00–6:20 через API и печатает ✓ по каждому шагу | Брусникин Максим |
| Стек не поднимается совсем | Не чинить на защите. Показать видео (если готово — Ф12 в [23](23-mvp-plan.md)) или слайды 5–13 и вывод `make verify`, сохранённый при подготовке | Шиншин Алексей |
| Комиссия просит показать 1С | Сказать прямо: 1С-контур не реализован, демо-база не выдана. Показать слайды 20–21 и `docs/29-1c-target.md` §13 | Завгороднев Ярослав |
| Не хватает времени | Пропустить шаги 5:40–6:20 (карточка кода и проверка кода). Их покрывают слайды 8 и 13 | Шиншин Алексей |

## 5. Вопросы, к которым стоит подготовиться

| Вопрос | Короткий ответ | Где подробнее |
|---|---|---|
| Почему K1 после демо ниже 99%? | K1 считает и намеренные отказы: два отказа из 879 попыток. На эталонном наборе K1 = 99,19% | README «Замечания для показа» |
| Почему повторный импорт не создаёт дублей? | Ключи `op_id` и `(code, ts)`, сравнение с ранее отклонёнными строками по содержимому, транзакция на строку | [26](26-data-mapping.md) §4, [28](28-api.md) §6 |
| Что будет, если ЦРПТ недоступен? | Таймаут 2 с, отказ `MOCK_UNAVAILABLE`, статус не меняется. Повтор с тем же `op_id` безопасен | [28](28-api.md) §7.1 |
| Почему не 1С? | Кейс допускает 1С «при наличии у заказчика»; демо-база не выдана. Целевой контур описан до уровня объектов | [29](29-1c-target.md) §0 |
| Кто проверяет права? | Backend на каждом запросе. Интерфейс только скрывает кнопки | [28](28-api.md) §3 |
| Откуда эталон, если правила пишет та же команда? | Эталон строит генератор по тем ошибкам, которые он сам внедрил. Код backend генератор не использует | `tools/gen/README.md`, риск R13 в [16](16-risk-matrix.md) |
