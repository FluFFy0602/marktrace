# 05. Матрица конкурентов

> Сведения о конкурентах — по общеизвестным возможностям продуктов, без цифр тарифов. Столбец «Цена» нужно сверить с актуальными тарифами перед защитой.

## Конкуренты

| Тип | Продукт | Что делает |
|---|---|---|
| Прямой | Личный кабинет ГИС МТ «Честный знак» (оператор ЦРПТ) | Эмиссия и учёт кодов, операции ввода/вывода, отчёты по товарной группе |
| Прямой | Контур.Маркировка | Облачный сервис для работы с кодами, документы и отчёты по маркировке |
| Прямой | СБИС (Тензор), модуль маркировки | Учёт кодов и обмен с ГИС МТ в связке с ЭДО |
| Косвенный | Типовые решения 1С (подсистема маркировки в 1С:ERP, 1С:УНФ, 1С:Розница) | Коды внутри учётной системы, связь с ГИС МТ |
| Заменитель | Ручной учёт в Excel/CSV + проверки скриптами | Бесплатно, но без контроля переходов и отчёта расхождений |

## Сравнение

| Критерий | ЛК ГИС МТ | Контур.Маркировка | СБИС | 1С (типовые) | Excel | **MarkTrace (макет)** |
|---|---|---|---|---|---|---|
| Модель монетизации | бесплатно для участника, платные коды | подписка | подписка | лицензия 1С + обновления | бесплатно | не коммерческий |
| Реальная интеграция с ГИС МТ | да | да | да | да | нет | **нет (мок)** |
| Контроль допустимых переходов статусов | базовый, на стороне оператора | да | да | да | нет | **да, правила настраиваемы и видны** |
| Отчёт «статусы + расхождения» с причинами | ограниченный | да | да | зависит от конфигурации | вручную | **да, с причиной отклонения и CSV** |
| Проверка формата кода и контрольной цифры GTIN | да | да | да | да | нет | **да, версия правил в отчёте** |
| Идемпотентный импорт CSV | нет | частично | частично | зависит от конфигурации | нет | **да, по `op_id` и `code+ts`** |
| Прозрачность модели для обучения (открытые правила, синтетика) | нет | нет | нет | нет | нет | **да** |
| Порог входа | регистрация, УКЭП | регистрация, УКЭП | регистрация, УКЭП | настройка конфигурации | низкий | **низкий, без УКЭП** |
| Слабые места | не показывает внутренние ошибки вашего учёта | платный, закрытая логика | платный, привязан к экосистеме | сложная настройка, дорогая доработка | ошибки и дубли | **не работает с боевыми данными** |
| Технологический стек | веб | веб/облако | веб/облако | платформа 1С | — | Go, PostgreSQL, React + REST-мок |

## SWOT продукта

| | Положительное | Отрицательное |
|---|---|---|
| **Внутреннее** | **S:** правила кейса реализованы явно; эталонные наборы T1; идемпотентный импорт; прозрачная трассировка отклонений | **W:** нет боевой интеграции; условная маска кода; малая команда |
| **Внешнее** | **O:** постоянное расширение товарных групп и ужесточение требований; рост спроса на проверку данных до загрузки; макет как учебный стенд | **T:** изменения правил ЦРПТ делают макет неактуальным; готовые сервисы закрывают потребность; расхождение с реальной структурой кода |

## Инсайты → требования

| Инсайт | Потребность | Требование | Критерий |
|---|---|---|---|
| Готовые сервисы показывают ошибку, но не объясняют, какой переход нарушен | Понятная причина отклонения | Хранить и показывать причину каждого отклонения (M6) | В `violations.csv` у каждой строки заполнена `reason` |
| Повторная загрузка выписок плодит дубли | Безопасный повтор | Идемпотентный импорт (M7) | 0 новых строк при повторе |
| Статус в реестре и журнал операций расходятся | Один источник истины | Статус рассчитывается из последней валидной операции | K2 = 100% |
| Проверку кода нельзя отработать без УКЭП и боевого доступа | Безопасный стенд | REST-мок `/cz/verify` с управляемыми ошибками (M10, S3) | Три сценария ошибок воспроизводятся |
| Разбор расхождений идёт вручную в Excel | Единый отчёт и экспорт | Отчёт «Расхождения» + CSV (M5, M6) | Экспорт совпадает с эталоном |

## Вывод

Конкуренты сильнее в реальной интеграции и юридической значимости. Наше преимущество — учебная прозрачность: видимые правила, причины отклонений, эталонные наборы и безопасный стенд без УКЭП.
